# Описание Sequence-диаграмм для модуля «Заявки на обучение»

## 1. Sequence-диаграмма UC-01 «Создание заявки на обучение»

### Назначение диаграммы

Sequence-диаграмма **UC-01 «Создание заявки на обучение»** описывает последовательность взаимодействий между Заявителем, Порталом, БД Портала, СДО и Почтовой службой при создании новой заявки на обучение.

Диаграмма отражает процесс от открытия формы создания заявки до сохранения заявки в системе со статусом «Ожидает рассмотрения» либо «Черновик».

### Участники диаграммы

| Участник            | Назначение                                                                              |
| ------------------- | --------------------------------------------------------------------------------------- |
| **Заявитель**       | Пользователь, создающий заявку на обучение.                                             |
| **Портал**          | Основная система, обеспечивающая заполнение формы, проверку данных и сохранение заявки. |
| **БД Портала**      | Хранилище заявок, данных учеников, статусов и истории изменений.                        |
| **СДО**             | Внешняя система, предоставляющая актуальный список курсов.                              |
| **Почтовая служба** | Внешний сервис для отправки уведомлений.                                                |

### Основная последовательность взаимодействий

1. Заявитель переходит в модуль «Заявки на обучение».
2. Портал отображает список заявок и доступное действие «Создать заявку».
3. Заявитель нажимает кнопку «Создать заявку».
4. Портал открывает форму создания заявки.
5. Портал автоматически добавляет сведения о Заявителе и его организации.
6. Заявитель выполняет поиск курса по названию.
7. Портал отправляет запрос в СДО для получения актуального списка курсов.
8. СДО возвращает список курсов, соответствующих поисковому запросу.
9. Портал отображает найденные курсы в форме заявки.
10. Заявитель выбирает курс по полному названию и датам проведения.
11. Портал заполняет данные о датах обучения.
12. Заявитель добавляет учеников вручную через веб-форму или загружает список учеников из Excel-файла.
13. При ручном добавлении Заявитель вводит часть Ф.И.О. ученика.
14. Портал выполняет поиск ученика и отображает найденные записи.
15. Заявитель выбирает нужного ученика.
16. Портал автоматически заполняет оставшиеся обязательные поля ученика.
17. При загрузке Excel-файла Портал проверяет формат файла и отображает список учеников в форме заявки.
18. Заявитель при необходимости редактирует список учеников.
19. Заявитель нажимает кнопку «Отправить».
20. Портал выполняет валидацию заявки: проверяет обязательные поля, формат данных и наличие дублей.
21. Если заявка корректна, Портал сохраняет её в БД.
22. БД Портала фиксирует заявку, список учеников, статус и историю создания.
23. Портал присваивает заявке статус «Ожидает рассмотрения».
24. Портал передаёт уведомление через Почтовую службу.
25. Почтовая служба отправляет уведомление Согласующему.
26. Портал отображает Заявителю сообщение «Заявка успешно отправлена».

### Альтернативные фрагменты диаграммы

#### Alt: сохранение заявки как черновика

1. Заявитель нажимает кнопку «Сохранить как черновик».
2. Портал выполняет проверку доступных данных.
3. Портал сохраняет заявку в БД со статусом «Черновик».
4. БД Портала фиксирует черновик заявки.
5. Портал отображает сообщение об успешном сохранении черновика.

#### Alt: загрузка ранее сохранённого черновика

1. Заявитель нажимает кнопку «Загрузить черновик».
2. Портал запрашивает данные черновика в БД.
3. БД Портала возвращает сохранённые данные.
4. Портал отображает черновик в форме заявки.
5. Заявитель продолжает заполнение заявки.

#### Alt: загрузка учеников из Excel

1. Заявитель нажимает кнопку «Импорт из Excel».
2. Заявитель выбирает файл для загрузки.
3. Портал принимает файл и проверяет его формат.
4. Если файл корректен, Портал отображает список учеников в форме заявки.
5. Заявитель проверяет и редактирует загруженные данные.

### Исключительные фрагменты диаграммы

#### Alt: Excel-файл имеет некорректный формат

1. Портал выявляет ошибку формата Excel-файла.
2. Портал не загружает данные учеников в заявку.
3. Портал отображает сообщение с причиной ошибки.
4. Заявитель выбирает другой файл или исправляет текущий.

#### Alt: заявка не прошла валидацию

1. Портал выявляет незаполненные обязательные поля, некорректные данные или дубли учеников.
2. Портал визуально выделяет проблемные поля или записи.
3. Портал отображает сообщение с причиной ошибки.
4. Заявитель исправляет данные.
5. Заявитель повторно отправляет заявку на рассмотрение.

### Рекомендуемые UML-фрагменты

Для диаграммы UC-01 рекомендуется использовать:

| Фрагмент | Назначение                                                  |
| -------- | ----------------------------------------------------------- |
| **alt**  | Разделение успешной и неуспешной валидации.                 |
| **opt**  | Сохранение заявки как черновика.                            |
| **alt**  | Выбор способа добавления учеников: вручную или через Excel. |
| **loop** | Повторное добавление нескольких учеников вручную.           |

## 2. Sequence-диаграмма UC-02 «Просмотр списка заявок»

### Назначение диаграммы

Sequence-диаграмма **UC-02 «Просмотр списка заявок»** описывает последовательность взаимодействий между Пользователем, Порталом и БД Портала при просмотре списка заявок.

Диаграмма отражает получение списка заявок с учётом роли пользователя, а также поиск, фильтрацию, сортировку, пагинацию, выбор заявок, скачивание данных и переход в карточку заявки.

### Участники диаграммы

| Участник         | Назначение                                                             |
| ---------------- | ---------------------------------------------------------------------- |
| **Пользователь** | Авторизованный пользователь Портала с определённой ролью в модуле.     |
| **Заявитель**    | Пользователь, просматривающий собственные заявки.                      |
| **Согласующий**  | Пользователь, просматривающий заявки, доступные ему по ролевой модели. |
| **Портал**       | Система, формирующая и отображающая список заявок.                     |
| **БД Портала**   | Хранилище заявок, статусов, ролей и прав доступа.                      |

### Основная последовательность взаимодействий

1. Пользователь переходит в модуль «Заявки на обучение».
2. Портал определяет роль Пользователя в рамках модуля.
3. Портал формирует запрос к БД Портала на получение списка заявок.
4. БД Портала проверяет доступность заявок согласно ролевой модели.
5. Если Пользователь является Заявителем, БД возвращает заявки, созданные этим Заявителем.
6. Если Пользователь является Согласующим, БД возвращает заявки, доступные ему для просмотра и рассмотрения.
7. Портал получает список заявок.
8. Портал отображает список заявок в табличной форме.
9. Портал отображает необходимые столбцы таблицы.
10. Портал отображает текущий статус каждой заявки.
11. Портал отображает только действия, доступные Пользователю согласно его роли.
12. Портал отображает элементы выбора количества заявок на странице.
13. Портал отображает элементы пагинации.
14. Пользователь просматривает список заявок.
15. Сценарий завершается отображением списка заявок, доступных Пользователю.

### Альтернативные фрагменты диаграммы

#### Alt: Пользователь выполняет поиск

1. Пользователь вводит поисковый запрос.
2. Портал передаёт поисковый запрос в БД Портала.
3. БД выполняет поиск только среди заявок, доступных Пользователю.
4. БД возвращает найденные заявки.
5. Портал отображает результат поиска.

#### Alt: Пользователь применяет фильтры

1. Пользователь выбирает параметры фильтрации.
2. Портал передаёт параметры фильтрации в БД Портала.
3. БД применяет фильтры к заявкам, доступным Пользователю.
4. БД возвращает отфильтрованный список заявок.
5. Портал отображает отфильтрованный список.

#### Alt: Пользователь сортирует список заявок

1. Пользователь выбирает столбец или параметр сортировки.
2. Портал передаёт параметр сортировки в БД Портала.
3. БД возвращает отсортированный список заявок.
4. Портал обновляет табличное представление.

#### Alt: Пользователь меняет количество заявок на странице

1. Пользователь выбирает количество заявок на странице.
2. Портал обновляет параметры отображения списка.
3. Портал запрашивает данные с учётом нового размера страницы.
4. БД возвращает соответствующий набор заявок.
5. Портал обновляет таблицу.

#### Alt: Пользователь переходит между страницами

1. Пользователь выбирает страницу списка.
2. Портал запрашивает данные выбранной страницы.
3. БД возвращает заявки с учётом текущих фильтров, поиска и сортировки.
4. Портал отображает выбранную страницу.

#### Alt: Пользователь выбирает несколько заявок

1. Пользователь отмечает одну или несколько заявок в таблице.
2. Портал фиксирует выбранные заявки.
3. Портал проверяет доступные групповые действия.
4. Портал отображает действия, доступные для выбранных заявок.

#### Alt: Пользователь скачивает отфильтрованный список заявок

1. Пользователь инициирует скачивание отфильтрованного списка.
2. Портал запрашивает в БД данные с учётом текущих фильтров и прав доступа.
3. БД возвращает данные для выгрузки.
4. Портал формирует файл.
5. Портал предоставляет файл Пользователю для скачивания.

#### Alt: Пользователь скачивает выбранные заявки

1. Пользователь выбирает несколько заявок.
2. Пользователь инициирует скачивание выбранных заявок.
3. Портал проверяет доступ Пользователя к выбранным заявкам.
4. Портал формирует файл или архив.
5. Портал предоставляет файл или архив для скачивания.

#### Alt: Пользователь открывает карточку заявки

1. Пользователь выбирает заявку из списка.
2. Портал проверяет доступ к выбранной заявке.
3. Портал запрашивает полные данные заявки в БД Портала.
4. БД возвращает данные заявки.
5. Портал открывает карточку заявки.
6. Пользователь просматривает карточку заявки.

#### Alt: Пользователь удаляет черновик

1. Пользователь выбирает заявку в статусе «Черновик».
2. Пользователь нажимает кнопку удаления.
3. Портал проверяет право на удаление черновика.
4. Портал отправляет запрос на удаление в БД.
5. БД удаляет черновик или помечает его как удалённый.
6. Портал обновляет список заявок.

### Исключительные фрагменты диаграммы

#### Alt: у Пользователя нет доступных заявок

1. БД не находит заявки, доступные Пользователю.
2. Портал отображает пустую таблицу.
3. Портал отображает сообщение об отсутствии доступных заявок.

#### Alt: по поиску или фильтрам заявки не найдены

1. БД не находит заявки, соответствующие поиску или фильтрам.
2. Портал отображает пустой результат.
3. Портал предлагает изменить поисковый запрос или сбросить фильтры.

#### Alt: Пользователь пытается открыть заявку без доступа

1. Портал выявляет отсутствие доступа к выбранной заявке.
2. Портал запрещает открытие карточки.
3. Портал отображает сообщение об отсутствии прав доступа.

#### Alt: ошибка формирования файла для скачивания

1. Портал не может сформировать файл выгрузки.
2. Портал отображает сообщение об ошибке.
3. Пользователь может повторить попытку скачивания.

### Рекомендуемые UML-фрагменты

Для диаграммы UC-02 рекомендуется использовать:

| Фрагмент | Назначение                                                                                    |
| -------- | --------------------------------------------------------------------------------------------- |
| **alt**  | Разделение отображения списка по роли: Заявитель / Согласующий.                               |
| **opt**  | Поиск, фильтрация, сортировка, скачивание или удаление черновика как необязательные действия. |
| **loop** | Переход между страницами списка заявок.                                                       |
| **alt**  | Проверка доступа при открытии карточки заявки.                                                |

## 3. Sequence-диаграмма UC-03 «Рассмотрение заявки»

### Назначение диаграммы

Sequence-диаграмма **UC-03 «Рассмотрение заявки»** описывает последовательность взаимодействий между Согласующим, Порталом, БД Портала, Заявителем, Почтовой службой и СДО при рассмотрении заявки.

Диаграмма отражает процесс открытия карточки заявки, проверки прав доступа, анализа данных заявки, согласования, отклонения или отправки заявки на доработку.

### Участники диаграммы

| Участник            | Назначение                                                                          |
| ------------------- | ----------------------------------------------------------------------------------- |
| **Согласующий**     | Пользователь, проверяющий заявку и принимающий решение.                             |
| **Заявитель**       | Пользователь, создавший заявку.                                                     |
| **Портал**          | Система, обеспечивающая проверку прав, отображение карточки и смену статуса заявки. |
| **БД Портала**      | Хранилище заявок, статусов, истории решений и комментариев.                         |
| **СДО**             | Внешняя система, в которую передаётся согласованная заявка.                         |
| **Почтовая служба** | Внешний сервис для отправки email-уведомлений.                                      |

### Основная последовательность взаимодействий

1. Согласующий открывает список заявок.
2. Портал запрашивает в БД список заявок, доступных Согласующему.
3. БД возвращает список заявок согласно ролевой модели.
4. Портал отображает список заявок.
5. Согласующий выбирает заявку для рассмотрения.
6. Портал запрашивает данные выбранной заявки в БД.
7. БД возвращает данные заявки, список учеников, текущий статус, автора заявки, комментарии и историю.
8. Портал проверяет права доступа Согласующего к заявке.
9. Портал проверяет, что Согласующий не является создателем заявки.
10. Портал проверяет, что заявка находится в статусе, доступном для рассмотрения.
11. Портал открывает карточку заявки.
12. Портал отображает основные данные заявки.
13. Портал отображает список учеников.
14. Портал отображает текущий статус заявки.
15. Портал отображает комментарии и историю заявки.
16. Портал отображает действия, доступные Согласующему.
17. Согласующий проверяет данные заявки и список учеников.
18. Согласующий нажимает кнопку «Согласовать».
19. Портал выполняет контрольную проверку заявки перед согласованием.
20. Портал обновляет статус заявки в БД.
21. БД фиксирует новый статус, решение Согласующего и запись в истории заявки.
22. Портал отображает Согласующему сообщение об успешном изменении статуса.
23. Портал передаёт уведомление Заявителю через Почтовую службу.
24. Почтовая служба отправляет email-уведомление Заявителю.
25. Портал отображает заявку в списке с обновлённым статусом.
26. Портал инициирует передачу согласованной заявки в СДО через API.
27. СДО принимает заявку и возвращает результат обработки.
28. Портал фиксирует результат передачи заявки в БД.

### Альтернативные фрагменты диаграммы

#### Alt: Согласующий скачивает заявку

1. Согласующий нажимает кнопку скачивания заявки.
2. Портал запрашивает данные заявки в БД.
3. БД возвращает данные для формирования файла.
4. Портал формирует файл заявки.
5. Портал предоставляет файл Согласующему.

#### Alt: Согласующий отклоняет заявку

1. Согласующий нажимает кнопку «Отклонить».
2. Портал отображает поле для ввода комментария.
3. Согласующий указывает причину отклонения.
4. Портал проверяет наличие комментария.
5. Портал обновляет статус заявки на «Отклонена».
6. БД сохраняет статус, комментарий, решение Согласующего и запись в истории.
7. Портал передаёт уведомление Заявителю через Почтовую службу.
8. Почтовая служба отправляет email-уведомление.
9. Портал отображает заявку в списке со статусом «Отклонена».

#### Alt: Согласующий отправляет заявку на доработку

1. Согласующий нажимает кнопку «Отправить на доработку».
2. Портал отображает поле для ввода комментария.
3. Согласующий указывает детали, которые необходимо скорректировать.
4. Портал проверяет наличие комментария.
5. Портал обновляет статус заявки на «На доработке».
6. БД сохраняет статус, комментарий, решение Согласующего и запись в истории.
7. Портал передаёт уведомление Заявителю через Почтовую службу.
8. Почтовая служба отправляет email-уведомление Заявителю.
9. Портал отображает заявку в списке со статусом «На доработке».

#### Alt: Согласующий работает со списком учеников

1. Согласующий выполняет поиск, фильтрацию или сортировку списка учеников.
2. Портал применяет выбранные параметры к списку учеников.
3. Портал обновляет отображение списка учеников.
4. Согласующий продолжает рассмотрение заявки.

#### Alt: Согласующий меняет количество учеников на странице или переходит между страницами

1. Согласующий выбирает количество учеников на странице или номер страницы.
2. Портал обновляет параметры отображения.
3. Портал отображает соответствующую часть списка учеников.
4. Согласующий продолжает проверку заявки.

### Исключительные фрагменты диаграммы

#### Alt: Согласующий пытается рассмотреть собственную заявку

1. Портал сравнивает Согласующего с автором заявки.
2. Портал выявляет, что Согласующий является создателем заявки.
3. Портал запрещает рассмотрение заявки.
4. Портал отображает сообщение о невозможности рассматривать собственную заявку.
5. Согласующий возвращается к списку заявок.

#### Alt: у Согласующего нет доступа к выбранной заявке

1. Портал проверяет права доступа.
2. Портал выявляет отсутствие доступа к выбранной заявке.
3. Портал запрещает открытие или рассмотрение заявки.
4. Портал отображает сообщение об отсутствии прав доступа.
5. Согласующий возвращается к списку заявок.

#### Alt: заявка находится в статусе, недоступном для рассмотрения

1. Портал проверяет текущий статус заявки.
2. Портал выявляет, что заявка недоступна для рассмотрения.
3. Портал открывает карточку заявки только для просмотра.
4. Портал не отображает действия «Согласовать», «Отклонить» и «Отправить на доработку».

#### Alt: комментарий при отклонении не указан

1. Согласующий нажимает кнопку «Отклонить».
2. Портал требует комментарий.
3. Согласующий не указывает комментарий.
4. Портал запрещает отклонение заявки.
5. Портал отображает сообщение о необходимости указать причину отклонения.

#### Alt: комментарий при отправке на доработку не указан

1. Согласующий нажимает кнопку «Отправить на доработку».
2. Портал требует комментарий.
3. Согласующий не указывает комментарий.
4. Портал запрещает возврат заявки на доработку.
5. Портал отображает сообщение о необходимости указать детали корректировки.

#### Alt: ошибка при передаче заявки в СДО

1. Портал передаёт согласованную заявку в СДО через API.
2. СДО возвращает ошибку или не возвращает ответ.
3. Портал фиксирует ошибку передачи.
4. Портал выполняет повторную отправку в пределах установленного лимита.
5. Если передача остаётся неуспешной, Портал сохраняет сведения об ошибке в БД.
6. БД фиксирует статус «Ошибка СДО».
7. Портал уведомляет Согласующего о необходимости повторной обработки.

Для диаграммы UC-03 рекомендуется использовать:

| Фрагмент | Назначение                                                                         |
| -------- | ---------------------------------------------------------------------------------- |
| **alt**  | Разделение решения Согласующего: согласовать / отклонить / отправить на доработку. |
| **alt**  | Проверка прав доступа и запрет рассмотрения собственной заявки.                    |
| **opt**  | Скачивание заявки.                                                                 |
| **opt**  | Поиск, фильтрация, сортировка и пагинация списка учеников.                         |
| **loop** | Повторная отправка заявки в СДО при ошибке API.                                    |
| **alt**  | Успешная или неуспешная передача заявки в СДО.                                     |
