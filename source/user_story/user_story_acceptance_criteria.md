# User Story и критерии приёмки для модуля «Заявки на обучение»

## US-01. Создание заявки на обучение

Как Заявитель, я хочу создать заявку на обучение через веб-форму, чтобы централизованно направить сотрудников своей организации на выбранный курс.

**Критерии приёмки:**

- Заявитель может открыть форму создания заявки в модуле «Заявки на обучение».
    
- Заявитель может заполнить основные данные заявки: курс, даты проведения обучения, преподавателя и иные обязательные поля.
    
- Заявитель может добавить список учеников вручную через веб-форму.
    
- Заявитель может скачать шаблон Excel-файла для заполнения списка учеников.
    
- Заявитель может загрузить список учеников из Excel-файла установленного формата.
    
- После загрузки Excel-файла система отображает список учеников в форме заявки.
    
- Заявитель может вручную отредактировать список учеников после загрузки Excel-файла.
    
- Система проверяет заполненность обязательных полей и корректность данных перед отправкой заявки.
    
- При ошибках валидации система отображает сообщение с причиной ошибки.
    
- При успешной отправке система сохраняет заявку и присваивает ей статус «Ожидает рассмотрения».
    
- Заявитель может сохранить незавершённую заявку как черновик.
    
- Заявитель может загрузить ранее сохранённый черновик и продолжить заполнение заявки.
    
- Заявитель может удалить ненужный черновик.

## US-02. Просмотр списка заявок

Как Пользователь модуля, я хочу просматривать список заявок с возможностью поиска, фильтрации и сортировки, чтобы быстро находить нужные заявки и отслеживать их состояние.

**Критерии приёмки:**

- Заявитель может просматривать список своих заявок.
    
- Согласующий может просматривать список всех заявок, доступных ему в соответствии с ролевой моделью.
    
- Администратор может просматривать все заявки без ограничений по автору или организации.
    
- В списке заявок для Заявителя отображаются основные сведения: номер заявки, Название курса, Согласующий, Статус, Дата создания заявки, Дата изменения заявки.
     
- В списке заявок для Согласующего и Администратора отображаются основные сведения: номер заявки, Название курса, Организация, Заявитель, Согласующий, Статус, Дата создания заявки, Дата изменения заявки.
    
- Пользователь может открыть карточку выбранной заявки из списка.
    
- Пользователь может выполнять поиск заявки по названию курса.
    
- Пользователь может фильтровать заявки по согласующему, статусу, названию курса и датам.
    
- Согласующий может также фильтровать заявки по организации, заявителю.
    
- Пользователь может сортировать заявки по номеру заявки, названию курса, согласующему и дате обновления заявки.
    
- Заявитель не может видеть заявки, созданные другими Заявителями.
    
- Система отображает только те действия с заявками, которые доступны пользователю согласно его роли.
    
- Пользователь может скачать список заявок, доступных ему по роли.
    
- Пользователь может просмотреть карточку заявки с основными данными, списком учеников, статусом, комментариями.

## US-03. Рассмотрение заявки

Как Согласующий, я хочу проверить заявку и принять по ней решение, чтобы корректные заявки были переданы в СДО, а некорректные были отклонены или возвращены Заявителю на доработку.

**Критерии приёмки:**
- В карточке заявки Согласующий видит основные данные заявки, список учеников, текущий статус, комментарии и историю изменений.
    
- Согласующий не может рассматривать заявку, которую он сам создал.
    
- Согласующий может согласовать корректную заявку.
    
- При согласовании система меняет статус заявки на «Согласована».
    
- После согласования система инициирует передачу заявки в СДО через API.
    
- Согласующий может отклонить заявку, если она не может быть принята.
    
- При отклонении система меняет статус заявки на «Отклонена».
    
- При отклонении Согласующий может указать комментарий с причиной отклонения.
    
- Согласующий может отправить заявку на доработку, если в ней есть исправимые ошибки.
    
- При отправке на доработку комментарий Согласующего является обязательным.
    
- При отправке на доработку система меняет статус заявки на «На корректировку».
    
- Заявитель может отредактировать заявку, возвращённую на корректировку, и повторно отправить её на рассмотрение.
    
- При каждом изменении статуса система формирует уведомление на Портале.
    
- При каждом изменении статуса система передаёт данные в Почтовую службу для отправки email-уведомления.
    
- Если передача согласованной заявки в СДО завершилась ошибкой, система фиксирует ошибку и переводит заявку в статус, требующий повторной обработки.
