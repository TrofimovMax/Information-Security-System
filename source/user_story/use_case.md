# Use Case для модуля «Заявки на обучение»

## UC-01. Создание заявки на обучение

| Поле | Описание |
|---|---|
| **ID** | UC-01 |
| **Название** | Создание заявки на обучение |
| **Действующие лица** | **Заявитель** — пользователь, создающий заявку на обучение.<br>**Система** — модуль Портала «Заявки на обучение».<br>**СДО** — внешняя система, предоставляющая актуальный список курсов. |
| **Цель** | Ускорить процесс подачи и обработки, и сохранить данные в истории. |
| **Триггер** | Пользователь инициирует создание по кнопке «Создать заявку». |
| **Предварительные условия** | Пользователь авторизован на Портале.<br>Сессия активна. |
| **Выходные условия** | Созданная заявка сохранена в системе.<br>Заявке присвоен соответствующий статус. |
| **Основной сценарий** | **ОС1. Успешное создание и отправка заявки на обучение через веб-форму.**<br>1. Система добавляет информацию о Заявителе и об организации Заявителя.<br>2. Заявитель ищет курс через поиск по его названию.<br>3. Система запрашивает список актуальных курсов в СДО и предоставляет результат поиска.<br>4. Заявитель выбирает курс по полному названию и датам проведения.<br>5. Система заполняет данные о датах обучения в форме.<br>6. Заявитель в пустой таблице учеников инициирует добавление ученика по нажатию на «Добавить ученика».<br>7. Заявитель в новой строке колонки Ф.И.О. ученика вводит часть фамилии ученика.<br>8. Система делает поисковый запрос ученика и отображает учеников, найденных по запросу.<br>9. Заявитель выбирает нужного ученика из найденного списка.<br>10. Система заполняет оставшиеся обязательные поля.<br>11. Заявитель инициирует отправку заявки по нажатию на «Отправить».<br>12. Система производит валидацию заявки и при успешной валидации сохраняет заявку и присваивает ей соответствующий статус.<br>13. Система отправляет результат Заявителю.<br>14. Заявитель видит сообщение «Заявка успешно отправлена». |
| **Альтернативные сценарии** | **АС1. Загрузить черновик.**<br>1. После шага 1 сценария ОС1.<br>2. Заявитель инициирует загрузку черновика по нажатию на «Загрузить черновик».<br>3. Система загружает черновик и отображает данные в заявке.<br>4. Выполнение переходит на шаг, с которого перешли в альтернативный сценарий.<br><br>**АС2. Заполнить нескольких учеников вручную через веб-форму.**<br>1. Шаг 6 сценария ОС1.<br>2. Повторить шаги 6–10 сценария ОС1 необходимое количество раз.<br>3. Переход к шагу 11 сценария ОС1.<br><br>**АС3. Скачать шаблон для загрузки списка учеников.**<br>1. В любой момент между шагом 1 и шагом 11 сценария ОС1.<br>2. Заявитель инициирует скачивание шаблона по нажатию на «Скачать шаблон».<br>3. Система скачивает файл.<br>4. Выполнение переходит на шаг, с которого перешли в альтернативный сценарий.<br><br>**АС4. Загрузить учеников через импорт из Excel.**<br>1. После шага 6 сценария ОС1.<br>2. Заявитель инициирует загрузку файла по нажатию на «Импорт из Excel» и выбирает файл для загрузки.<br>3. Система загружает выбранный файл для валидации, производит валидацию и при успешной валидации отправляет список учеников для отображения Заявителю.<br>4. Заявитель переходит к шагу 11 сценария ОС1.<br><br>**АС5. Сохранить как черновик.**<br>1. После шага 10 сценария ОС1.<br>2. Заявитель инициирует сохранение заявки в качестве черновика по нажатию на «Сохранить как черновик».<br>3. Переход к шагу 12 сценария ОС1.<br><br>**АС6. Удаление ученика из списка учеников.**<br>1. После шага 10 сценария ОС1 или альтернативных сценариев.<br>2. Заявитель выбирает ученика и инициирует его удаление из списка по нажатию на «Удалить».<br>3. Возврат на шаг 6 сценария ОС1 или выполнение переходит на шаг, с которого перешли в альтернативный сценарий. |
| **Исключения** | **ИС1. Excel-файл имеет некорректный формат.**<br>1. После шага 3 сценария АС4.<br>2. Система формирует сообщение с подробностями об ошибках с загруженным файлом.<br>3. Возвращение на шаг 2 сценария АС4.<br><br>**ИС2. Система выделяет незаполненные обязательные поля.**<br>1. Шаг 12 сценария ОС1.<br>2. Система формирует сообщение с незаполненными полями и показывает их Заявителю.<br>3. Возврат на шаг 2 сценария ОС1.<br><br>**ИС3. Система выделяет дубли в списке учеников.**<br>1. Шаг 12 сценария ОС1.<br>2. Система формирует поля-дубликаты и визуально выделяет их для Заявителя.<br>3. Возврат на шаг 1 сценария АС6. |

## UC-02. Просмотр списка заявок

| Поле | Описание |
|---|---|
| **ID** | UC-02 |
| **Название** | Просмотр списка заявок |
| **Действующие лица** | **Пользователь** — авторизованный на Портале пользователь с определённой ролью в рамках модуля «Заявки на обучение».<br>**Система** — модуль Портала «Заявки на обучение». |
| **Цель** | Быстро находить нужные заявки и отслеживать их состояние. |
| **Триггер** | Пользователь переходит в модуль Портала «Заявки на обучение». |
| **Предварительные условия** | Пользователь авторизован на Портале.<br>Сессия пользователя активна. |
| **Выходные условия** | Пользователь просмотрел список заявок, доступных ему согласно ролевой модели.<br>Пользователь может открыть карточку выбранной заявки.<br>При необходимости пользователь может скачать список заявок или выбранные заявки.<br>Пользователь может удалить черновик из списка заявок. |
| **Основной сценарий** | **ОС1. Успешный просмотр списка заявок, доступных пользователю по роли.**<br>1. Система формирует список заявок, доступных Пользователю согласно ролевой модели.<br>2. Пользователь просматривает список заявок. |
| **Альтернативные сценарии** | **АС1. Пользователь выполняет поиск по списку заявок.**<br>1. После шага 1 сценария ОС1 Пользователь вводит поисковый запрос в поле поиска.<br>2. Система выполняет поиск только по заявкам, доступным Пользователю согласно ролевой модели.<br>3. Система отображает найденные заявки в табличной форме.<br>4. Выполнение возвращается к шагу 2 сценария ОС1.<br><br>**АС2. Пользователь фильтрует список заявок.**<br>1. После шага 1 сценария ОС1 Пользователь выбирает параметры фильтрации списка заявок.<br>2. Система применяет выбранные фильтры только к заявкам, доступным Пользователю согласно ролевой модели.<br>3. Система отображает отфильтрованный список заявок.<br>4. Выполнение возвращается к шагу 2 сценария ОС1.<br><br>**АС3. Пользователь сортирует список заявок.**<br>1. После шага 1 сценария ОС1 Пользователь выбирает столбец или параметр сортировки списка заявок.<br>2. Система сортирует список заявок по выбранному параметру.<br>3. Система отображает отсортированный список заявок.<br>4. Выполнение возвращается к шагу 2 сценария ОС1.<br><br>**АС4. Пользователь выбирает количество заявок, отображаемых на странице.**<br>1. После шага 1 сценария ОС1 Пользователь выбирает количество заявок, отображаемых на одной странице.<br>2. Система применяет выбранное значение.<br>3. Система обновляет табличное представление списка заявок.<br>4. Выполнение возвращается к шагу 2 сценария ОС1.<br><br>**АС5. Пользователь переходит между страницами списка заявок.**<br>1. После шага 1 сценария ОС1 Пользователь выбирает страницу списка заявок.<br>2. Система запрашивает и отображает заявки выбранной страницы с учётом текущих фильтров, поиска и сортировки.<br>3. Выполнение возвращается к шагу 2 сценария ОС1.<br><br>**АС6. Пользователь выбирает несколько заявок.**<br>1. После шага 1 сценария ОС1 Пользователь выбирает одну или несколько заявок в списке.<br>2. Система фиксирует выбранные заявки.<br>3. Система выделяет выбранные заявки.<br>4. Выполнение возвращается к шагу 2 сценария ОС1.<br><br>**АС7. Пользователь скачивает отфильтрованный список заявок.**<br>1. После выполнения сценария АС2 Пользователь инициирует скачивание отфильтрованного списка заявок.<br>2. Система формирует файл со списком заявок, доступных Пользователю согласно ролевой модели и выбранным фильтрам.<br>3. Система предоставляет файл для скачивания.<br>4. Выполнение возвращается к шагу 2 сценария ОС1.<br><br>**АС8. Пользователь скачивает выбранные заявки для просмотра.**<br>1. После выполнения сценария АС6 Пользователь инициирует скачивание выбранных заявок.<br>2. Система проверяет, что выбранные заявки доступны Пользователю согласно ролевой модели.<br>3. Система формирует файл или архив с выбранными заявками.<br>4. Система загружает файл или архив.<br>5. Выполнение возвращается к шагу 2 сценария ОС1.<br><br>**АС9. Пользователь открывает карточку выбранной заявки.**<br>1. После шага 1 сценария ОС1 Пользователь выбирает заявку из списка.<br>2. Система проверяет доступ Пользователя к выбранной заявке согласно ролевой модели.<br>3. Система открывает карточку выбранной заявки.<br>4. Система отображает все данные выбранной заявки.<br>5. Выполнение сценария завершается просмотром карточки заявки.<br><br>**АС10. Пользователь удаляет черновик из списка заявок.**<br>1. После шага 1 сценария ОС1 Пользователь выбирает заявку в статусе «Черновик».<br>2. Пользователь инициирует удаление черновика из списка заявок.<br>3. Система проверяет, что Пользователь имеет право удалить выбранный черновик.<br>4. Система удаляет черновик из списка заявок.<br>5. Система обновляет список заявок.<br>6. Выполнение возвращается к шагу 2 сценария ОС1. |
| **Исключения** | — |

## UC-03. Рассмотрение заявки

| Поле | Описание |
|---|---|
| **ID** | UC-03 |
| **Название** | Рассмотрение заявки |
| **Действующие лица** | **Согласующий** — пользователь, проверяющий заявку и принимающий решение.<br>**Заявитель** — пользователь, создавший заявку.<br>**Система** — модуль Портала «Заявки на обучение». |
| **Цель** | Проверить заявку и принять по ней решение, чтобы корректные заявки были переданы в СДО. |
| **Триггер** | Согласующий переходит к рассмотрению заявки. |
| **Предварительные условия** | Пользователь авторизован на Портале как Согласующий.<br>Сессия пользователя активна.<br>Заявка доступна Согласующему в соответствии с ролевой моделью.<br>Заявка находится в статусе, доступном для рассмотрения.<br>Согласующий не является создателем рассматриваемой заявки. |
| **Выходные условия** | По заявке принято решение.<br>Статус заявки изменён на соответствующий принятому решению.<br>Решение Согласующего сохранено в системе.<br>При отклонении сохранён комментарий с причиной отклонения.<br>При отправке на доработку сохранён комментарий с деталями, которые нужно скорректировать.<br>После принятия решения заявка отображается в списке заявок с соответствующим статусом.<br>Заявка скачана. |
| **Основной сценарий** | **ОС1. Успешное рассмотрение и согласование заявки.**<br>1. Система проверяет права доступа Согласующего к выбранной заявке.<br>2. Система проверяет, что Согласующий не является создателем выбранной заявки.<br>3. Система проверяет, что заявка находится в статусе, доступном для рассмотрения.<br>4. Система открывает карточку заявки.<br>5. Система отображает все необходимые поля карточки заявки.<br>6. Система отображает действия, доступные Согласующему для рассмотрения заявки.<br>7. Согласующий проверяет данные заявки и список учеников.<br>8. Согласующий инициирует согласование заявки по нажатию на кнопку «Согласовать».<br>9. Система выполняет контрольную проверку заявки перед согласованием.<br>10. Система меняет статус заявки на соответствующий.<br>11. Система отображает Согласующему сообщение об успешном изменении статуса заявки.<br>12. Заявка отображается в списке заявок с соответствующим статусом. |
| **Альтернативные сценарии** | **АС1. Согласующий скачивает заявку.**<br>1. Шаг 7 сценария ОС1.<br>2. Согласующий инициирует скачивание заявки нажав на «Скачать заявку».<br>3. Система формирует файл заявки для скачивания.<br>4. Система предоставляет файл Согласующему.<br>5. Выполнение возвращается к шагу 7 сценария ОС1.<br><br>**АС2. Согласующий отклоняет заявку.**<br>1. После шага 7 сценария ОС1 Согласующий решает, что заявка не может быть принята.<br>2. Согласующий инициирует отклонение заявки по нажатию на кнопку «Отклонить».<br>3. Система отображает поле для ввода комментария с причиной отклонения и отключает кнопку «Отклонить».<br>4. Согласующий указывает комментарий с причиной отклонения.<br>5. Система проверяет наличие комментария.<br>6. Если комментарий указан, Система включает кнопку «Отклонить».<br>7. Согласующий повторно инициирует отклонение заявки по нажатию на кнопку «Отклонить».<br>8. Система сохраняет комментарий в истории комментариев.<br>9. Переход на шаг 10 сценария ОС1.<br><br>**АС3. Согласующий отправляет заявку на доработку.**<br>1. После шага 7 сценария ОС1 Согласующий выявляет исправимые ошибки в заявке.<br>2. Согласующий инициирует возврат заявки на доработку по нажатию на кнопку «Отправить на доработку».<br>3. Система отображает поле для ввода комментария с деталями, которые нужно скорректировать, и отключает кнопку «Отправить на доработку».<br>4. Согласующий указывает комментарий с деталями, которые нужно скорректировать.<br>5. Система проверяет наличие комментария.<br>6. Если комментарий указан, Система включает кнопку «Отправить на доработку».<br>7. Согласующий повторно инициирует возврат заявки на доработку по нажатию на кнопку «Отправить на доработку».<br>8. Система сохраняет комментарий в истории комментариев.<br>9. Переход на шаг 10 сценария ОС1.<br><br>**АС4. Согласующий сортирует список учеников.**<br>1. После шага 7 сценария ОС1 Согласующий выбирает параметр сортировки списка учеников.<br>2. Система сортирует список учеников по выбранному параметру.<br>3. Система отображает отсортированный список учеников.<br>4. Выполнение возвращается к шагу 7 сценария ОС1.<br><br>**АС5. Согласующий фильтрует список учеников.**<br>1. После шага 7 сценария ОС1 Согласующий выбирает параметры фильтрации списка учеников.<br>2. Система применяет выбранные фильтры.<br>3. Система отображает отфильтрованный список учеников.<br>4. Выполнение возвращается к шагу 7 сценария ОС1.<br><br>**АС6. Согласующий выполняет поиск по списку учеников.**<br>1. После шага 7 сценария ОС1 Согласующий вводит поисковый запрос по списку учеников.<br>2. Система выполняет поиск по списку учеников.<br>3. Система отображает найденные записи.<br>4. Выполнение возвращается к шагу 7 сценария ОС1.<br><br>**АС7. Согласующий выбирает количество учеников, отображаемых на странице.**<br>1. После шага 7 сценария ОС1 Согласующий выбирает количество учеников, отображаемых на странице.<br>2. Система применяет выбранное значение.<br>3. Система обновляет отображение списка учеников.<br>4. Выполнение возвращается к шагу 7 сценария ОС1.<br><br>**АС8. Согласующий переходит между страницами списка учеников.**<br>1. После шага 7 сценария ОС1 Согласующий выбирает страницу списка учеников.<br>2. Система отображает выбранную страницу списка учеников.<br>3. Выполнение возвращается к шагу 7 сценария ОС1. |
| **Исключения** | **ИС1. Согласующий пытается рассмотреть заявку, которую сам создал.**<br>1. На шаге 2 сценария ОС1 Система выявляет, что Согласующий является создателем выбранной заявки.<br>2. Система открывает карточку заявки.<br>3. Система отображает все необходимые поля карточки заявки без отображения действий для рассмотрения заявки.<br>4. Согласующий может взаимодействовать с заявкой как Заявитель.<br><br>**ИС2. Заявка находится в статусе, недоступном для рассмотрения.**<br>1. На шаге 3 сценария ОС1 Система выявляет, что заявка находится в статусе, недоступном для рассмотрения.<br>2. Система не отображает действия «Согласовать», «Отклонить» и «Отправить на доработку».<br>3. Система отображает карточку заявки только для просмотра.<br>4.
