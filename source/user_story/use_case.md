### Основной сценарий

**Название:** Успешное создание и отправка заявки на обучение через веб-форму

1. Пользователь выбирает действие «Создать заявку».
    
2. Система открывает веб-форму создания заявки.
    
3. Система отображает все необходимые поля формы заявки.
    
4. Система автоматически заполняет данные о Заявителе: Ф.И.О., номер телефона, электронную почту и название организации.
    
5. Пользователь заполняет обязательные поля и прочие данные заявки.
    
6. Пользователь добавляет список учеников вручную через веб-форму.
    
7. При вводе Ф.И.О. ученика система автоматически заполняет доступные данные ученика из справочника сотрудников.
    
8. При необходимости Пользователь скачивает шаблон Excel-файла для заполнения списка учеников.
    
9. При необходимости Пользователь загружает Excel-файл со списком учеников установленного формата.
    
10. Система проверяет формат и структуру Excel-файла.
    
11. Система отображает загруженный список учеников в форме заявки.
    
12. Пользователь при необходимости вручную редактирует список учеников после загрузки Excel-файла.
    
13. Пользователь при необходимости выполняет поиск по списку учеников.
    
14. Пользователь при необходимости фильтрует список учеников.
    
15. Пользователь при необходимости сортирует список учеников.
    
16. Система отображает список учеников с использованием пагинации.
    
17. Пользователь нажимает кнопку отправки заявки.
    
18. Система проверяет заполненность обязательных полей и корректность данных заявки.
    
19. Система проверяет список учеников на наличие дублей.
    
20. Система сохраняет заявку.
    
21. Система присваивает заявке соответствующий статус.
    
22. Система сохраняет данные заявки в истории.
    
23. Система отображает Пользователю сообщение об успешном создании заявки.
    

---

### Альтернативные сценарии

#### Альтернативный сценарий 1. Пользователь сохраняет заявку как черновик

1. Пользователь открывает форму создания заявки.
    
2. Пользователь заполняет часть данных заявки.
    
3. Пользователь выбирает действие «Сохранить как черновик».
    
4. Система сохраняет введённые данные заявки.
    
5. Система присваивает заявке статус «Черновик».
    
6. Система отображает сообщение об успешном сохранении черновика.
    

---

#### Альтернативный сценарий 2. Пользователь загружает ранее сохранённый черновик

1. Пользователь выбирает действие «Загрузить черновик».
    
2. Система отображает список ранее сохранённых черновиков, доступных Пользователю.
    
3. Пользователь выбирает нужный черновик.
    
4. Система открывает форму заявки с ранее сохранёнными данными.
    
5. Пользователь продолжает заполнение заявки.
    
6. Далее сценарий продолжается с редактирования заявки, загрузки списка учеников или отправки заявки.
    

---

#### Альтернативный сценарий 3. Пользователь заполняет список учеников только вручную

1. Пользователь открывает форму создания заявки.
    
2. Пользователь заполняет основные данные заявки.
    
3. Пользователь добавляет учеников вручную через веб-форму.
    
4. При вводе Ф.И.О. ученика система автоматически заполняет доступные данные ученика.
    
5. Пользователь проверяет список учеников.
    
6. Пользователь отправляет заявку.
    
7. Система выполняет проверку данных и сохраняет заявку при успешной валидации.
    

---

#### Альтернативный сценарий 4. Пользователь заполняет список учеников через Excel-файл

1. Пользователь открывает форму создания заявки.
    
2. Пользователь скачивает шаблон Excel-файла.
    
3. Пользователь заполняет шаблон списком учеников.
    
4. Пользователь загружает заполненный Excel-файл в форму заявки.
    
5. Система проверяет формат и структуру файла.
    
6. Система переносит данные учеников из файла в форму заявки.
    
7. Система отображает загруженный список учеников.
    
8. Пользователь при необходимости редактирует список учеников вручную.
    
9. Пользователь отправляет заявку.
    
10. Система выполняет проверку данных и сохраняет заявку при успешной валидации.
    

---

#### Альтернативный сценарий 5. Пользователь редактирует список учеников после загрузки Excel-файла

1. Пользователь загружает Excel-файл со списком учеников.
    
2. Система отображает загруженный список учеников в форме заявки.
    
3. Пользователь изменяет данные отдельных учеников.
    
4. Пользователь добавляет новых учеников или удаляет ошибочные записи.
    
5. Система обновляет список учеников в форме заявки.
    
6. Пользователь отправляет заявку после завершения редактирования.
    

---

#### Альтернативный сценарий 6. Пользователь работает с большим списком учеников

1. Пользователь добавляет или загружает большой список учеников.
    
2. Система отображает список учеников с пагинацией.
    
3. Пользователь выполняет поиск по списку учеников.
    
4. Пользователь применяет фильтрацию списка учеников.
    
5. Пользователь применяет сортировку списка учеников.
    
6. Система отображает список учеников в соответствии с выбранными параметрами.
    
7. Пользователь продолжает создание или отправку заявки.
    

---

### Исключения

#### Исключение 1. Excel-файл имеет некорректный формат

1. Пользователь загружает Excel-файл.
    
2. Система проверяет структуру и формат файла.
    
3. Система обнаруживает, что файл не соответствует установленному формату.
    
4. Система не добавляет данные из файла в заявку.
    
5. Система отображает сообщение с причиной ошибки.
    
6. Пользователь может скачать шаблон Excel-файла и повторить загрузку.
    

---

#### Исключение 2. Обязательные поля заявки не заполнены

1. Пользователь нажимает кнопку отправки заявки.
    
2. Система проверяет заполненность обязательных полей.
    
3. Система обнаруживает незаполненные обязательные поля.
    
4. Система выделяет незаполненные обязательные поля в форме заявки.
    
5. Система не отправляет заявку на рассмотрение.
    
6. Система отображает сообщение с причиной ошибки.
    
7. Пользователь остаётся на форме создания заявки для исправления данных.
    

---

#### Исключение 3. В списке учеников обнаружены дубли

1. Пользователь добавляет учеников вручную или загружает список из Excel-файла.
    
2. Система проверяет список учеников на наличие дублей.
    
3. Система обнаруживает повторяющиеся записи.
    
4. Система выделяет дубли в списке учеников.
    
5. Система отображает сообщение с причиной ошибки.
    
6. Система не позволяет отправить заявку до устранения дублей.
    

---

#### Исключение 4. Данные заявки не проходят валидацию

1. Пользователь нажимает кнопку отправки заявки.
    
2. Система проверяет корректность введённых данных.
    
3. Система обнаруживает ошибку в данных заявки.
    
4. Система не сохраняет заявку как отправленную.
    
5. Система отображает сообщение с причиной ошибки валидации.
    
6. Пользователь исправляет данные и повторно отправляет заявку.
    

---

#### Исключение 5. Данные ученика не найдены при автоматическом заполнении по Ф.И.О.

1. Пользователь вводит Ф.И.О. ученика в веб-форме.
    
2. Система выполняет поиск данных ученика в справочнике сотрудников.
    
3. Система не находит сотрудника с указанным Ф.И.О.
    
4. Система не выполняет автоматическое заполнение данных ученика.
    
5. Система отображает сообщение о том, что данные ученика не найдены.
    
6. Пользователь может уточнить Ф.И.О. или заполнить данные ученика вручную, если это предусмотрено правилами системы.
    

---

#### Исключение 6. Черновик не может быть загружен

1. Пользователь выбирает действие «Загрузить черновик».
    
2. Система пытается открыть выбранный черновик.
    
3. Система обнаруживает, что черновик недоступен, удалён или повреждён.
    
4. Система не открывает черновик.
    
5. Система отображает сообщение о невозможности загрузить черновик.
    
6. Пользователь может выбрать другой черновик или создать новую заявку.

### Основной сценарий

#### Успешный просмотр списка заявок

1. Пользователь переходит в раздел со списком заявок модуля «Заявки на обучение».
    
2. Система определяет роль пользователя.
    
3. Система определяет перечень заявок, доступных пользователю согласно ролевой модели.
    
4. Если пользователь является Заявителем, система отображает только заявки, созданные этим Заявителем.
    
5. Если пользователь является Согласующим, система отображает список всех заявок, доступных ему в соответствии с ролевой моделью.
    
6. Если пользователь является Администратором, система отображает список всех заявок, доступных ему в соответствии с ролевой моделью.
    
7. Система отображает список заявок с основными сведениями.
    
8. Для Заявителя система отображает основные сведения о заявках, доступные ему по роли.
    
9. Для Согласующего и Администратора система отображает основные сведения о заявках, доступные им по роли.
    
10. Система отображает только те действия с заявками, которые доступны пользователю согласно его роли.
    
11. Пользователь при необходимости выполняет поиск по списку заявок.
    
12. Система отображает заявки, соответствующие поисковому запросу.
    
13. Пользователь при необходимости применяет фильтры к списку заявок.
    
14. Система отображает список заявок с учётом выбранных фильтров.
    
15. Пользователь при необходимости сортирует список заявок.
    
16. Система отображает отсортированный список заявок.
    
17. Пользователь выбирает заявку из списка.
    
18. Система открывает карточку выбранной заявки.
    
19. Система отображает карточку заявки со всеми данными, доступными пользователю по его роли.

### Альтернативные сценарии

#### Заявитель просматривает только свои заявки

1. Заявитель переходит в раздел со списком заявок.
    
2. Система определяет роль пользователя как «Заявитель».
    
3. Система формирует список заявок, созданных данным Заявителем.
    
4. Система отображает Заявителю только его заявки.
    
5. Заявки других Заявителей не отображаются в списке.
    
6. Заявитель может открыть карточку только своей заявки.
    

#### Согласующий просматривает заявки, доступные ему по роли

1. Согласующий переходит в раздел со списком заявок.
    
2. Система определяет роль пользователя как «Согласующий».
    
3. Система формирует список заявок, доступных Согласующему в соответствии с ролевой моделью.
    
4. Система отображает Согласующему доступные заявки.
    
5. Система отображает действия, доступные Согласующему по каждой заявке.
    
6. Согласующий может открыть карточку выбранной заявки.
    

#### Администратор просматривает заявки, доступные ему по роли

1. Администратор переходит в раздел со списком заявок.
    
2. Система определяет роль пользователя как «Администратор».
    
3. Система формирует список заявок, доступных Администратору в соответствии с ролевой моделью.
    
4. Система отображает Администратору доступные заявки.
    
5. Система отображает действия, доступные Администратору по каждой заявке.
    
6. Администратор может открыть карточку выбранной заявки.
    

#### Пользователь выполняет поиск по списку заявок

1. Пользователь находится в списке заявок.
    
2. Пользователь вводит поисковый запрос.
    
3. Система выполняет поиск по заявкам, доступным пользователю согласно его роли.
    
4. Система отображает заявки, соответствующие поисковому запросу.
    
5. Пользователь может открыть найденную заявку из списка.
    

#### Пользователь фильтрует список заявок

1. Пользователь находится в списке заявок.
    
2. Пользователь выбирает параметры фильтрации.
    
3. Система применяет фильтры только к заявкам, доступным пользователю согласно его роли.
    
4. Система отображает список заявок с учётом выбранных фильтров.
    
5. Пользователь может открыть заявку из отфильтрованного списка.
    

#### Пользователь сортирует список заявок

1. Пользователь находится в списке заявок.
    
2. Пользователь выбирает параметр сортировки.
    
3. Система сортирует заявки, доступные пользователю согласно его роли.
    
4. Система отображает отсортированный список заявок.
    
5. Пользователь может открыть заявку из отсортированного списка.
    

#### Пользователь скачивает отфильтрованный список заявок

1. Пользователь находится в списке заявок.
    
2. Пользователь при необходимости применяет поиск, фильтрацию или сортировку.
    
3. Пользователь выбирает действие «Скачать список заявок».
    
4. Система формирует файл выгрузки.
    
5. В файл попадают только заявки, доступные пользователю согласно его роли и текущим параметрам фильтрации.
    
6. Система загружает файл на устройство пользователя.
    

#### Пользователь скачивает выбранные заявки

1. Пользователь находится в списке заявок.
    
2. Пользователь выбирает одну или несколько заявок из списка.
    
3. Пользователь выбирает действие «Скачать выбранные заявки».
    
4. Система проверяет доступ пользователя к выбранным заявкам.
    
5. Система формирует файл или архив с выбранными заявками.
    
6. В выгрузку попадают только заявки, доступные пользователю согласно его роли.
    
7. Система загружает сформированный файл на устройство пользователя.

### Исключения

#### В системе отсутствуют заявки, доступные пользователю

1. Пользователь переходит в раздел со списком заявок.
    
2. Система определяет роль пользователя.
    
3. Система выполняет поиск заявок, доступных пользователю согласно его роли.
    
4. Система не находит доступных заявок.
    
5. Система отображает пустой список.
    
6. Система отображает сообщение об отсутствии доступных заявок.
    

#### Поиск не дал результатов

1. Пользователь вводит поисковый запрос.
    
2. Система выполняет поиск по заявкам, доступным пользователю согласно его роли.
    
3. Система не находит заявки, соответствующие поисковому запросу.
    
4. Система отображает сообщение об отсутствии результатов поиска.
    
5. Пользователь может изменить поисковый запрос или сбросить поиск.
    

#### Фильтрация не дала результатов

1. Пользователь выбирает параметры фильтрации.
    
2. Система применяет фильтры к заявкам, доступным пользователю согласно его роли.
    
3. Система не находит заявки, соответствующие выбранным параметрам.
    
4. Система отображает пустой список.
    
5. Система отображает сообщение об отсутствии заявок по выбранным фильтрам.
    
6. Пользователь может изменить параметры фильтрации или сбросить фильтры.
    

#### Пользователь пытается открыть заявку, недоступную ему по роли

1. Пользователь пытается открыть карточку заявки, доступ к которой не предусмотрен его ролью.
    
2. Система проверяет права доступа пользователя к выбранной заявке.
    
3. Система запрещает открытие карточки заявки.
    
4. Система отображает сообщение об отсутствии прав доступа.
    
5. Пользователь остаётся в списке доступных ему заявок.
    

#### Пользователь пытается выполнить действие, недоступное ему по роли

1. Пользователь пытается выполнить действие с заявкой.
    
2. Система проверяет доступность действия согласно роли пользователя.
    
3. Система запрещает выполнение действия.
    
4. Система отображает сообщение о недостаточности прав.
    
5. Система не изменяет данные заявки.
    

#### Система не может сформировать файл выгрузки

1. Пользователь выбирает действие скачивания списка заявок или выбранных заявок.
    
2. Система пытается сформировать файл выгрузки.
    
3. При формировании файла возникает ошибка.
    
4. Система не загружает файл на устройство пользователя.
    
5. Система отображает сообщение о невозможности сформировать файл выгрузки.
    
6. Пользователь остаётся в списке заявок.

### Основной сценарий

#### Успешное рассмотрение и согласование заявки

1. Согласующий открывает список заявок.
    
2. Согласующий выбирает заявку в статусе «Ожидает рассмотрения».
    
3. Система открывает карточку заявки.
    
4. Система отображает основные данные заявки.
    
5. Система отображает список учеников.
    
6. Система отображает текущий статус заявки.
    
7. Система отображает комментарии.
    
8. Согласующий проверяет данные заявки.
    
9. Согласующий выбирает действие «Согласовать».
    
10. Система меняет статус заявки на «Согласована».
    
11. Система сохраняет факт изменения статуса в истории заявки.
    
12. Система формирует уведомление на Портале для Заявителя.
    
13. Система передаёт данные в Почтовую службу для отправки email-уведомления.
    
14. Система инициирует передачу согласованной заявки в СДО через API.
    
15. Система фиксирует результат передачи заявки в СДО.
    

---

### Альтернативные сценарии

#### Согласующий отклоняет заявку

1. Согласующий открывает заявку в статусе «Ожидает рассмотрения».
    
2. Согласующий проверяет данные заявки.
    
3. Согласующий принимает решение отклонить заявку.
    
4. Согласующий выбирает действие «Отклонить».
    
5. При необходимости Согласующий указывает комментарий с причиной отклонения.
    
6. Система меняет статус заявки на «Отклонена».
    
7. Система сохраняет комментарий Согласующего при его наличии.
    
8. Система сохраняет факт изменения статуса в истории заявки.
    
9. Система формирует уведомление на Портале для Заявителя.
    
10. Система передаёт данные в Почтовую службу для отправки email-уведомления.
    

#### Согласующий отправляет заявку на доработку

1. Согласующий открывает заявку в статусе «Ожидает рассмотрения».
    
2. Согласующий проверяет данные заявки.
    
3. Согласующий обнаруживает исправимые ошибки.
    
4. Согласующий выбирает действие «Отправить на доработку».
    
5. Согласующий указывает обязательный комментарий с описанием необходимых исправлений.
    
6. Система меняет статус заявки на «На корректировку».
    
7. Система сохраняет комментарий Согласующего.
    
8. Система сохраняет факт изменения статуса в истории заявки.
    
9. Система формирует уведомление на Портале для Заявителя.
    
10. Система передаёт данные в Почтовую службу для отправки email-уведомления.
    
11. Заявитель получает возможность отредактировать заявку и повторно отправить её на рассмотрение.
    

---

### Исключения

#### Согласующий пытается отправить заявку на доработку без комментария

1. Согласующий выбирает действие «Отправить на доработку».
    
2. Согласующий не заполняет комментарий.
    
3. Согласующий пытается подтвердить действие.
    
4. Система не выполняет перевод заявки в статус «На корректировку».
    
5. Система не сохраняет решение по заявке.
    
6. Система отображает признак обязательности комментария или сообщение о необходимости заполнить комментарий.
    
7. Согласующий остаётся в карточке заявки.
    

#### Согласующий пытается рассмотреть собственную заявку

1. Согласующий открывает заявку, которую он сам создал.
    
2. Система определяет, что Согласующий является автором заявки.
    
3. Система блокирует действия «Согласовать», «Отклонить» и «Отправить на доработку».
    
4. Согласующий может только просмотреть заявку в рамках доступных ему прав.
    

#### Передача согласованной заявки в СДО завершилась ошибкой

1. Согласующий согласовывает заявку.
    
2. Система меняет статус заявки на «Согласована».
    
3. Система инициирует передачу заявки в СДО через API.
    
4. СДО возвращает ошибку или не принимает заявку.
    
5. Система фиксирует ошибку передачи.
    
6. Система переводит заявку в статус, требующий повторной обработки Согласующим.
    
7. Система сохраняет информацию об ошибке в истории заявки.
    
8. Система формирует уведомление ответственным пользователям.
