# Use Case для модуля «Заявки на обучение»

## UC-01. Создание заявки на обучение

**User Story:**  
Как Заявитель, я хочу создать заявку на обучение через веб-форму, чтобы централизованно направить сотрудников своей организации на выбранный курс.

**Название:** Создать заявку на обучение

**Действующие лица:**

- Заявитель — пользователь, создающий заявку на обучение.
    
- Система — модуль Портала «Заявки на обучение».
    
- СДО — внешняя система, предоставляющая актуальный список курсов.
    
- Active Directory — источник данных о сотрудниках.
    
- Почтовая служба — внешняя система для отправки email-уведомлений.
    

**Предварительные условия:**

1. Заявитель авторизован на Портале.
    
2. Заявитель имеет права на создание заявки.
    
3. Заявитель находится в модуле «Заявки на обучение».
    
4. Система имеет доступ к актуальному каталогу курсов.
    
5. Система имеет доступ к данным сотрудников, необходимым для заполнения заявки.
    
6. Система поддерживает загрузку Excel-файла установленного формата.
    

**Успешный сценарий:**

1. Заявитель выбирает действие «Создать заявку».
    
2. Система открывает веб-форму создания заявки.
    
3. Заявитель заполняет основные данные заявки: курс, даты проведения обучения.
    
4. Система заполняет данные о Заявителе: Ф.И.О. Заявителя, номер телефона, электронная почта и название организации Заявителя.
    
5. Заявитель добавляет список учеников вручную через веб-форму.
    
6. При необходимости Заявитель скачивает шаблон Excel-файла для заполнения списка учеников.
    
7. При необходимости Заявитель загружает Excel-файл со списком учеников.
    
8. Система проверяет формат Excel-файла.
    
9. Система отображает загруженный список учеников в форме заявки.
    
10. Заявитель при необходимости вручную редактирует список учеников после загрузки Excel-файла.
    
11. Заявитель нажимает кнопку отправки заявки.
    
12. Система проверяет заполненность обязательных полей и корректность данных.
    
13. Система сохраняет заявку.
    
14. Система присваивает заявке статус «Ожидает рассмотрения».
    
15. Система отображает Заявителю сообщение об успешном создании заявки.
    
16. Система формирует уведомление на Портале о создании заявки.
    
17. Система при необходимости передаёт данные в Почтовую службу для отправки email-уведомления заинтересованным лицам.
    

**Альтернативные пути:**

**Название:** Заявитель сохраняет заявку как черновик

1. Заявитель заполняет часть данных заявки.
    
2. Заявитель выбирает действие «Сохранить как черновик».
    
3. Система сохраняет введённые данные.
    
4. Система присваивает заявке статус «Черновик».
    
5. Система отображает сообщение об успешном сохранении черновика.
    

**Название:** Заявитель загружает ранее сохранённый черновик

1. Заявитель выбирает действие «Загрузить черновик».
    
2. Система отображает доступные черновики Заявителя.
    
3. Заявитель выбирает нужный черновик.
    
4. Система открывает форму заявки с ранее сохранёнными данными.
    
5. Заявитель продолжает заполнение заявки.
    

**Название:** Заявитель удаляет черновик

1. Заявитель открывает список доступных черновиков.
    
2. Заявитель выбирает ненужный черновик.
    
3. Заявитель выбирает действие «Удалить черновик».
    
4. Система удаляет выбранный черновик.
    
5. Система больше не отображает удалённый черновик в списке.
    

**Название:** Excel-файл имеет некорректный формат

1. Заявитель загружает Excel-файл.
    
2. Система проверяет структуру и формат файла.
    
3. Система обнаруживает несоответствие установленному шаблону.
    
4. Система не добавляет данные из файла в заявку.
    
5. Система отображает сообщение об ошибке.
    

**Название:** Обязательные поля заявки не заполнены

1. Заявитель нажимает кнопку отправки заявки.
    
2. Система проверяет заполненность обязательных полей.
    
3. Система обнаруживает незаполненные обязательные поля.
    
4. Система не отправляет заявку на рассмотрение.
    
5. Система отображает сообщение с причиной ошибки.
    
6. Заявитель остаётся на форме создания заявки для исправления данных.
    

**Название:** Данные заявки не проходят валидацию

1. Заявитель нажимает кнопку отправки заявки.
    
2. Система проверяет корректность введённых данных.
    
3. Система обнаруживает ошибку в данных заявки.
    
4. Система не создаёт заявку в статусе «Ожидает рассмотрения».
    
5. Система отображает причину ошибки валидации.
    
6. Заявитель исправляет данные и повторно отправляет заявку.

## UC-02. Просмотр списка заявок

**User Story:**  
Как Пользователь модуля, я хочу просматривать список заявок с возможностью поиска, фильтрации и сортировки, чтобы быстро находить нужные заявки и отслеживать их состояние.

**Название:** Просмотреть список заявок

**Действующие лица:**

- Заявитель — пользователь, просматривающий список своих заявок.
    
- Согласующий — пользователь, просматривающий заявки, доступные ему в соответствии с ролевой моделью.
    
- Администратор — пользователь, имеющий полный доступ ко всем заявкам.
    
- Система — модуль Портала «Заявки на обучение».
    

**Предварительные условия:**

1. Пользователь авторизован на Портале.
    
2. Пользователь имеет роль Заявителя, Согласующего или Администратора.
    
3. Пользователь находится в модуле «Заявки на обучение».
    
4. В системе существуют заявки на обучение.
    
5. Для пользователя определены права доступа к заявкам согласно ролевой модели.
    

**Успешный сценарий:**

1. Пользователь переходит в раздел со списком заявок.
    
2. Система определяет роль пользователя.
    
3. Если пользователь является Заявителем, система отображает только заявки, созданные этим Заявителем.
    
4. Если пользователь является Согласующим, система отображает список всех заявок, доступных ему в соответствии с ролевой моделью.
    
5. Если пользователь является Администратором, система отображает все заявки без ограничений по автору или организации.
    
6. Система отображает список заявок с основными сведениями.
    
7. Для Заявителя система отображает: номер заявки, название курса, согласующего, статус, дату создания заявки и дату изменения заявки.
    
8. Для Согласующего и Администратора система отображает: номер заявки, название курса, организацию, заявителя, согласующего, статус, дату создания заявки и дату изменения заявки.
    
9. Пользователь выполняет поиск заявки по названию курса.
    
10. Система отображает заявки, соответствующие поисковому запросу.
    
11. Пользователь применяет фильтры по согласующему, статусу, названию курса и датам.
    
12. Система отображает список заявок с учётом выбранных фильтров.
    
13. Если пользователь является Согласующим, система дополнительно позволяет фильтровать заявки по организации и заявителю.
    
14. Пользователь сортирует список заявок по номеру заявки, названию курса, согласующему или дате обновления заявки.
    
15. Система отображает отсортированный список заявок.
    
16. Пользователь выбирает заявку из списка.
    
17. Система открывает карточку выбранной заявки.
    
18. Система отображает в карточке основные данные заявки, список учеников, статус и комментарии.
    

**Альтернативные пути:**

**Название:** Заявитель пытается увидеть чужие заявки

1. Заявитель переходит в список заявок.
    
2. Система определяет роль пользователя.
    
3. Система отображает только заявки, созданные данным Заявителем.
    
4. Заявки других Заявителей не отображаются в списке.
    
5. Заявитель не получает доступ к карточкам чужих заявок.
    

**Название:** Поиск не дал результатов

1. Пользователь вводит поисковый запрос по названию курса.
    
2. Система выполняет поиск по доступным пользователю заявкам.
    
3. Система не находит заявки, соответствующие запросу.
    
4. Система отображает сообщение об отсутствии результатов.
    
5. Пользователь может изменить поисковый запрос или сбросить поиск.
    

**Название:** Фильтры не дали результатов

1. Пользователь выбирает параметры фильтрации.
    
2. Система применяет фильтры к списку доступных заявок.
    
3. Система не находит заявок, соответствующих выбранным параметрам.
    
4. Система отображает пустой список и сообщение об отсутствии заявок.
    
5. Пользователь может изменить или сбросить фильтры.
    

**Название:** Пользователь скачивает список заявок

1. Пользователь находится в списке заявок.
    
2. Пользователь применяет при необходимости поиск, фильтрацию или сортировку.
    
3. Пользователь выбирает действие «Скачать список заявок».
    
4. Система формирует файл выгрузки.
    
5. В файл попадают только заявки, доступные пользователю согласно его роли.
    
6. Система загружает файл на устройство пользователя.
    

**Название:** Пользователь не имеет прав на действие с заявкой

1. Пользователь открывает список заявок.
    
2. Система определяет роль пользователя.
    
3. Система скрывает или блокирует действия, недоступные пользователю по ролевой модели.
    
4. Пользователь видит только разрешённые действия.

## UC-03. Рассмотрение заявки

**User Story:**  
Как Согласующий, я хочу проверить заявку и принять по ней решение, чтобы корректные заявки были переданы в СДО, а некорректные были отклонены или возвращены Заявителю на доработку.

**Название:** Рассмотреть заявку на обучение

**Действующие лица:**

- Согласующий — пользователь, проверяющий заявку и принимающий решение.
    
- Заявитель — пользователь, создавший заявку.
    
- Система — модуль Портала «Заявки на обучение».
    
- СДО — внешняя система, принимающая согласованные заявки через API.
    
- Почтовая служба — внешняя система для отправки email-уведомлений.
    

**Предварительные условия:**

1. Согласующий авторизован на Портале.
    
2. Согласующий имеет права на рассмотрение заявок.
    
3. В системе существует заявка в статусе «Ожидает рассмотрения».
    
4. Согласующий не является автором рассматриваемой заявки.
    
5. Заявка содержит основные данные и список учеников.
    
6. Система имеет возможность отправлять уведомления на Портале.
    
7. Система имеет возможность передавать данные в Почтовую службу.
    
8. Система имеет доступ к API СДО для передачи согласованных заявок.
    

**Успешный сценарий:**

1. Согласующий открывает список заявок.
    
2. Согласующий выбирает заявку в статусе «Ожидает рассмотрения».
    
3. Система открывает карточку заявки.
    
4. Система отображает основные данные заявки.
    
5. Система отображает список учеников.
    
6. Система отображает текущий статус заявки.
    
7. Система отображает комментарии.
    
8. Согласующий проверяет данные заявки.
    
9. Согласующий выбирает действие «Согласовать».
    
10. Система меняет статус заявки на «Согласована».
    
11. Система сохраняет факт изменения статуса в истории заявки.
    
12. Система формирует уведомление на Портале для Заявителя.
    
13. Система передаёт данные в Почтовую службу для отправки email-уведомления.
    
14. Система инициирует передачу согласованной заявки в СДО через API.
    
15. Система фиксирует результат передачи заявки в СДО.
    

**Альтернативные пути:**

**Название:** Согласующий отклоняет заявку

1. Согласующий открывает заявку в статусе «Ожидает рассмотрения».
    
2. Согласующий проверяет данные заявки.
    
3. Согласующий принимает решение отклонить заявку.
    
4. Согласующий выбирает действие «Отклонить».
    
5. При необходимости Согласующий указывает комментарий с причиной отклонения.
    
6. Система меняет статус заявки на «Отклонена».
    
7. Система сохраняет комментарий Согласующего при его наличии.
    
8. Система формирует уведомление на Портале для Заявителя.
    
9. Система передаёт данные в Почтовую службу для отправки email-уведомления.
    

**Название:** Согласующий отправляет заявку на доработку

1. Согласующий открывает заявку в статусе «Ожидает рассмотрения».
    
2. Согласующий проверяет данные заявки.
    
3. Согласующий обнаруживает исправимые ошибки.
    
4. Согласующий выбирает действие «Отправить на доработку».
    
5. Согласующий указывает обязательный комментарий с описанием необходимых исправлений.
    
6. Система меняет статус заявки на «На корректировку».
    
7. Система сохраняет комментарий Согласующего.
    
8. Система сохраняет факт изменения статуса в истории заявки.
    
9. Система формирует уведомление на Портале для Заявителя.
    
10. Система передаёт данные в Почтовую службу для отправки email-уведомления.
    
11. Заявитель получает возможность отредактировать заявку и повторно отправить её на рассмотрение.
    

**Название:** Согласующий пытается отправить заявку на доработку без комментария

1. Согласующий выбирает действие «Отправить на доработку».
    
2. Согласующий не заполняет комментарий.
    
3. Согласующий пытается подтвердить действие.
    
4. Система не блокирует (disable) кнопку с этим действием.
    
5. Согласующий остаётся в карточке заявки.
    

**Название:** Согласующий пытается рассмотреть собственную заявку

1. Согласующий открывает заявку, которую он сам создал.
    
2. Система определяет, что Согласующий является автором заявки.
    
3. Система блокирует действия «Согласовать», «Отклонить» и «Отправить на доработку».
    

**Название:** Передача согласованной заявки в СДО завершилась ошибкой

1. Согласующий согласовывает заявку.
    
2. Система меняет статус заявки на «Согласована».
    
3. Система инициирует передачу заявки в СДО через API.
    
4. СДО возвращает ошибку или не принимает заявку.
    
5. Система фиксирует ошибку передачи.
    
6. Система переводит заявку в статус, требующий повторной обработки.
    
7. Система сохраняет информацию об ошибке в истории заявки.
    
8. Система формирует уведомление ответственным пользователям.
